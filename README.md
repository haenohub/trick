숲에서 시작해 바다로 이어지는 쿼터뷰 도트 판타지 RPG. 지역 2까지 플레이할 수 있습니다.

**8방향 아틀리에:** https://haenohub.github.io/trick/directions.html

## v0.19.0 통합 캐릭터·수동 성장·살아 있는 지역

- 4직업의 의상과 몸을 함께 그린 8방향 걷기·대기·공격과 방향별 피격 시트를 새로 생성했습니다. 별도 의상 합성을 없애고 무기만 측정한 손 위치에 연결합니다. 출처: `art/dressed-players.json`, `art/dressed-hurt.json`. 기존 96px·256색·4px 여백을 유지합니다.

- C에서 레벨당 12포인트를 +1 또는 정수 수량 입력으로 직접 배분합니다. 전직 이후 레벨에는 추가 2포인트가 있습니다. 이전 자동 성장 저장은 기존 능력치를 배분된 수치로 이전해 보존합니다. 새로운 레벨에는 자동 배분하지 않습니다. 장비 요구 조건은 같은 기본 능력치로 검사합니다.
- 숲의 잎·꽃잎·반딧불, 해안의 물결을 새 도트 시트로 추가했습니다. 180초 지역 주기 중 30초 동안 숲 개화는 채집 +1, 해안 밀물 선물은 리프 +25%를 제공합니다. 미니맵 아래 표시와 실제 보상이 같은 판정 시계를 사용합니다. 동작 줄이기 설정에서는 환경 애니메이션을 끕니다.
- 단계별 범위와 출시 검증 기준은 [RELEASE_STAGES.md](RELEASE_STAGES.md)를 참고하세요. 자동 검사 통과를 장시간 실기기 QA 또는 정식 출시 완료로 간주하지 않습니다.
- `node scripts/apply-dressed-players.mjs`, `node scripts/apply-ambient-art.mjs`로 생성 원본을 패킹한 뒤 빌드·로컬 8093 서버·`scripts/render-equipped-combat.py`·`scripts/record-equipped-combat.mjs`·빌드 순서로 복원할 수 있습니다. 일반 빌드에는 생성 도구가 필요하지 않습니다.
- 새 시스템 검사는 `tests/manual-allocation.test.mjs`, `tests/living-world.test.mjs`, `scripts/manual-stats-smoke.py`에 있습니다.

## v0.18.0 공격 모션·손 장착·능력치 성장

- 모든 72종의 걷기 8프레임 재생 주기를 0.64초에서 **1.28초**로 늘렸습니다. 실제 이동 속도와 대기 호흡 주기는 유지합니다.
- 플레이어 4직업·몬스터 60종의 **8방향 준비 3프레임 → 타격 2프레임 → 회복 2프레임**, 피격 1프레임을 새 이미지 원본 64장으로 제작했습니다. 약초술사는 서서 어깨 높이에서 준비한 뒤 손바닥을 내미는 시전으로 바꿨습니다. 방향별 원본을 분리하고 각 셀을 개별 추출·정렬해 인접 스프라이트가 섞이지 않도록 4px 투명 여백을 둡니다. 피해는 타격 단계에서만 적용됩니다.
- 무기 16종을 실제 손 장착용 **8방향 모습 128개**로 새로 생성했습니다. 원본의 손잡이 표시를 측정한 뒤 제거하고, 각 자세의 실제 손 위치에 회전 중심을 연결합니다. 손가락을 무기 위에 합성하며 의복은 머리·몸통·발 기준점을 따라갑니다. 필드·초상화·아틀리에에서 같은 장착 합성을 사용합니다.
- 레벨과 전직에 따라 근력·민첩·지능·체력·정신·행운이 직업별로 자동 성장합니다. **C**에서 기본 성장 수치와 장비를 포함한 공격력·마력·물리/마법 방어력·명중·회피율·치명타 확률/피해·최대 체력을 확인할 수 있습니다. 물리/마법 피해, 명중·회피·치명타 판정이 실제 전투에 반영됩니다.
- 장비 30종에 요구 레벨·직업·전직·기본 스탯과 능력치 보너스를 부여했습니다. 게임의 장착 판정·설명창·리프테일 도감이 같은 데이터를 사용하며, 장비 자신의 보너스로 요구 조건을 충족할 수 없습니다. 이전 저장의 성장 수치는 레벨에서 다시 계산합니다.
- **Space**를 누르거나 길게 누르면 0.2초마다 가까운 전리품을 하나씩, **초당 최대 5개** 획득합니다. 빠르게 반복해서 눌러도 같은 간격이 적용되고 게임 판정에서도 제한합니다.
- 새 아트의 출처는 `art/combat-cycles.json`, `art/held-weapons.json`에 기록했습니다. 원본이 있는 환경에서 `node scripts/apply-combat-cycles.mjs`, `npm run build`, `python3 scripts/render-equipped-combat.py`(dist 서버 8093), `node scripts/record-equipped-combat.mjs`, `npm run build` 순서로 재패킹합니다. 일반 배포는 커밋된 완성 PNG를 사용합니다.
- `npm test`는 77개 검사를 수행합니다. `scripts/progression-smoke.py`는 성장·장착 조건·장비 교체·모바일 설명·도감을, `scripts/equipment-art-smoke.py`는 10,752가지 실제 장착 렌더링과 5부위 교체/저장 복원을 확인합니다. 모션·입력·아틀리에 브라우저 검사도 함께 제공합니다.

## 개발과 실행

Node.js 24:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm test
npm start
```

`npm start`는 HTTP와 WebSocket 서버를 8080 포트에서 실행합니다. `/health`로 상태를 확인합니다. 브라우저의 설정 → 게임 서버 주소에 로컬 서버의 `/ws` 주소를 입력하면 온라인 모험으로 전환됩니다. 서버 모험은 기존 브라우저 모험과 분리됩니다.

정적 화면만 개발하려면 `npm run serve`를 사용할 수 있습니다. 코드를 바꾼 뒤 `npm run build`로 `dist`를 갱신합니다.

환경에 기본 npm 캐시 경로가 없다면 명령에 `--cache /workspace/.cache/leaftale-npm`을 추가하세요.

`npm test`는 콘텐츠 무결성, 모든 몬스터의 드롭 확률, 전투 보상, 제작의 원자성, 전직 8종, 회피, 저장 복원, 두 WebSocket 클라이언트의 동기화·채팅·서버 재시작 복원을 검증합니다.

Playwright Python과 Chromium이 준비된 환경에서는 정적 서버를 띄운 뒤:

```sh
python3 scripts/browser-smoke.py http://127.0.0.1:8080/
python3 scripts/combat-exploration-smoke.py http://127.0.0.1:8080/
python3 scripts/interface-smoke.py http://127.0.0.1:8080/
```

이 검사는 격리된 브라우저 프로필에서 실제 UI로 네 직업 전투·여덟 전직·제작·화단·도감·저장·모바일 화면을 확인합니다. 사용자의 저장 데이터는 건드리지 않습니다.

## 이미지 생성 아트

지역 1·2의 맵 10장, 직업 4종, 몬스터 60종, NPC 8명과 장비·아이템·스킬·효과·인터페이스를 실제 이미지 생성 도구로 제작했습니다. 몬스터의 네이티브 셀은 64×64·96×96·128×128, 플레이어/NPC는 96×96, 아이템은 32×32이며 최대 256색 공통 팔레트와 선명한 1픽셀 격자를 사용합니다.

72종 전체에 각각 8방향 걷기 8프레임·대기 8프레임과 576개 단독 방향 PNG를 제공합니다. 장비는 중립 몸체 4종과 직업/아이템별 레이어 48종을 같은 32자세×8방향으로 합성합니다. 아틀리에는 검색·방향 전환·모션 재생·PNG 다운로드를 지원합니다. 공격에는 방향별 새 8프레임 시트와 손 위치에 고정된 무기 레이어를 사용합니다. 생성 출처와 재패킹 절차는 위의 v0.18.0·v0.17.0 항목을 참고하세요.

배포 배열은 `site/assets/manifest.json`, 네이티브 PNG 1,004개의 원본 연결과 체크섬은 `art/generated-assets.json`에 기록합니다. 총 368개 아틀라스 중 장비 외형 57개는 필요한 때 불러옵니다. 옛 절반 해상도 요청은 완성된 `art/hd-sources.json`으로 대체했으며 `scripts/apply-storybook.mjs`는 현재 에셋을 재생성하는 도구가 아닙니다. 일반 빌드·배포는 커밋된 PNG만 사용합니다. 이전 버전의 기록은 [ART_REWORK.md](ART_REWORK.md)에 있습니다.

## 파일 구조

독립 HTML 리프테일 도감은 [`site/bestiary.html`](site/bestiary.html)입니다. 몬스터60종과 아이템102종의 서사·서식지·능력치·제작법·획득처·드롭 확률/수량을 검색하고 지역·사냥터·분류로 필터링할 수 있습니다. HTML 저장 및 필터 결과 전체 인쇄를 지원합니다. 다운로드한 파일의 텍스트 데이터는 오프라인으로 열리며, 이미지는 공개 에셋을 불러옵니다. `npm run build` 때 게임 데이터에서 자동으로 다시 생성됩니다. 화면 수정은 `templates/bestiary.html`, 데이터 연결은 `scripts/build-bestiary.mjs`에서 합니다.

- `site/data.js`: 맵·직업·몬스터·아이템·퀘스트 데이터.
- `site/world-layout.js`: 맵별 지형·충돌·출입구·서식 구역·건물 배치의 공유 기준.
- `site/core.js`: 브라우저와 서버가 공유하는 전투/성장/경제 판정.
- `site/combat.js`: 공격 범위·보스 패턴·직업 연계 설명.
- `site/exploration.js`: 발견 장소·보물함·고유 설명과 보상.
- `site/audio.js`: 직업·전투·탐험 효과음 합성.
- `site/controls.js`: 기본 단축키·물리 키 입력·저장 검증과 중복 검사.
- `site/renderer.js`: 쿼터뷰 렌더링과 스프라이트 애니메이션.
- `site/app.js`: 입력·메뉴·로컬 저장·네트워크 연결.
- `server/index.mjs`: 서버 권한 판정, 실시간 연결, 세션 저장.
- `scripts/`: 아트 생성·빌드·배포 검증·브라우저 검증.
- `tests/`: 콘텐츠·게임 규칙·온라인 서버 검증.
