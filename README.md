## v0.29.0 스킬 이펙트 원점·크기 보정과 짧은 피격

## 개발과 실행

Node.js 24:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm test
npm start
```

`npm start`는 HTTP와 WebSocket 서버를 8080 포트에서 실행합니다. `/health`로 상태를 확인합니다. 브라우저의 설정 → 게임 서버 주소에 로컬 서버의 `/ws` 주소를 입력하면 온라인 모험으로 전환됩니다. 서버 모험은 기존 브라우저 모험과 분리됩니다.

정적 화면만 개발하려면 `npm run serve`를 사용할 수 있습니다. 코드를 바꾼 뒤 `npm run build`로 `dist`를 갱신합니다.

환경에 기본 npm 캐시 경로가 없다면 명령에 `--cache /workspace/.cache/leaftale-npm`을 추가하세요.

지역 1·2의 맵 10장, 직업 4종, 몬스터 60종, NPC 8명과 장비·아이템·스킬·효과·인터페이스를 실제 이미지 생성 도구로 제작했습니다. 몬스터의 네이티브 셀은 64×64·96×96·128×128, 플레이어/NPC는 96×96, 아이템은 64×64이며 최대 256색 공통 팔레트와 선명한 1픽셀 격자를 사용합니다.

72종 전체에 각각 8방향 걷기 8프레임·대기 8프레임과 576개 단독 방향 PNG를 제공합니다. 플레이어는 직업 의상을 입은 통합 몸체와 별도 무기를 같은 32자세×8방향으로 합성합니다. 아틀리에는 검색·방향 전환·모션 재생·PNG 다운로드를 지원합니다. 공격에는 방향별 새 8프레임 시트와 손 위치에 고정된 무기 레이어를 사용합니다. 생성 출처와 재패킹 절차는 위의 버전별 기록을 참고하세요.

배포 배열은 `site/assets/manifest.json`, 네이티브 PNG 1,054개의 원본 연결과 체크섬은 `art/generated-assets.json`에 기록합니다. 총 418개 아틀라스 중 장비 외형은 필요한 때 불러옵니다. 옛 절반 해상도 요청은 완성된 `art/hd-sources.json`으로 대체했으며 `scripts/apply-storybook.mjs`는 현재 에셋을 재생성하는 도구가 아닙니다. 일반 빌드·배포는 커밋된 PNG만 사용합니다. 이전 버전의 기록은 [ART_REWORK.md](ART_REWORK.md)에 있습니다.

## 파일 구조

독립 HTML 리프테일 도감은 [`site/bestiary.html`](site/bestiary.html)입니다. 몬스터60종·아이템204종·소비품 제작법40종의 서사·서식지·능력치·제작법·획득처·드롭 확률/수량을 검색하고 지역·사냥터·분류로 필터링할 수 있습니다. HTML 저장 및 필터 결과 전체 인쇄를 지원합니다. 다운로드한 파일의 텍스트 데이터는 오프라인으로 열리며, 이미지는 공개 에셋을 불러옵니다. `npm run build` 때 게임 데이터에서 자동으로 다시 생성됩니다. 화면 수정은 `templates/bestiary.html`, 데이터 연결은 `scripts/build-bestiary.mjs`에서 합니다.

- `site/data.js`: 맵·직업·몬스터·아이템·퀘스트 데이터.
- `site/world-layout.js`: 맵별 지형·충돌·출입구·서식 구역·건물 배치의 공유 기준.
- `site/core.js`: 브라우저와 서버가 공유하는 전투/성장/경제 판정.
- `site/combat.js`: 공격 범위·보스 패턴·직업 연계 설명.
- `site/exploration.js`: 발견 장소·보물함·고유 설명과 보상.
- `site/audio.js`: 직업·전투·탐험 효과음 합성.
- `site/controls.js`: 기본 단축키·물리 키 입력·저장 검증과 중복 검사.
- `site/renderer.js`: 쿼터뷰 렌더링과 스프라이트 애니메이션.
- `site/app.js`: 입력·메뉴·로컬 저장·네트워크 연결.
- `server/index.mjs`: 서버 권한 판정, 실시간 연결, 세션 저장.
- `scripts/`: 아트 생성·빌드·배포 검증·브라우저 검증.
- `tests/`: 콘텐츠·게임 규칙·온라인 서버 검증.

배포는 [DEPLOYMENT.md](DEPLOYMENT.md), 서버 운영은 [server/README.md](server/README.md)를 참고하세요.
